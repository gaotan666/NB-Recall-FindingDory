## 二、从原始模型重新训练

```bash
cd /home/gaotan/VDisk2/冲榜新/提交2
envs/model/bin/python 创建复现目录.py --mode retrain --out /home/gaotan/VDisk2/冲榜新/提交2_重训
cd /home/gaotan/VDisk2/冲榜新/提交2_重训

# 1. Stage A：从原始 Qwen 训练建库 LoRA，三卡、两轮。
bash scripts/submission2_pipeline.sh stage-a

# 2. 用新建库权重生成训练／校准预测，构造标签，拟合并校准两个 Trust Head。
bash scripts/submission2_pipeline.sh stage-b

# 3. 用冻结的建库权重处理完整 1478 个训练视频，每视频 96 帧。
bash scripts/submission2_pipeline.sh memory train

# 4. 生成问题＋检索记忆＋READ/GATE 监督。
bash scripts/submission2_pipeline.sh train-data

# 5. 从原始 Qwen 新建答题 LoRA，训练 3100 步；建库权重不参与更新。
bash scripts/submission2_pipeline.sh stage-c

# 6. 处理 100 个 validation 视频；准备 8 帧完整帧包及 episode 38 对齐数据。
bash scripts/submission2_pipeline.sh memory validation
bash scripts/submission2_pipeline.sh eval-data

# 7. 答题。不会自动进行仿真。
bash scripts/submission2_pipeline.sh answer

# 8. 确认要测官方 HL 指标时，单独执行。
bash scripts/submission2_pipeline.sh hl
```

`retrain` 工作目录不会加载历史建库／答题 LoRA，不会复制旧的生成记忆、Trust 标签、答题训练表或报告；这些由新训练出的模型重新生成。原始模型与大型原始数据仍通过链接复用。已生成输出的训练阶段会拒绝覆盖；不自动重启失败的训练。

新训练入口指定 3100 步，保存对应 checkpoint；历史训练原计划 6994 步、在 3100 步停止。训练表和原始 run.json 已归档，重训的随机计算与新生成记忆可能导致结果差异，不保证重新得到同一权重或恰好 42.6%。

## 三、原始数据如何产生

原始资源：`data/findingdory-subsampled-96` 提供训练／validation 视频和问题表；`data/findingdory-habitat` 提供仿真 episode；HSSD、物体和机器人资产用于仿真。依赖列表与绝对路径见 `归档清单.json`，软件包版本见 `environment/`。

Stage A 使用 `data/sim_replay/train/ep_*/observed.jsonl` 和对应 RGB 图像。`scripts/replay_train_experience.py` 回放官方训练轨迹并记录可见物体、框、位置、深度、时间与动作；`scripts/collect_train_batch.py` 可批量采集。`scripts/build_stage_a_append_only_data.py` 将这些训练场景信息转成 APPEND 标签与历史关系，并按场景分割 train/calibration/audit。

归档已经保存当时的 `data/stage_a_append_only/{train,calibration,audit}.jsonl`，建议重训先直接使用它们。若要重新采集原始仿真数据，必须先把工作副本中的 `data/sim_replay` 软链接换成新的普通目录，再运行采集脚本，避免写回共享数据。例如：

```bash
# 仅在新工作副本中执行，且确认该路径仍是软链接。
test -f REPRODUCTION_WORKSPACE.json
test -L data/sim_replay
unlink data/sim_replay
mkdir -p data/sim_replay/train logs
export PYTHONPATH="$PWD/vendor/findingdory-habitat:$PWD"
CUDA_VISIBLE_DEVICES=0 envs/habitat/bin/python scripts/replay_train_experience.py --episode 3 --save-every 5
# 按 environment/stage_a_episode_ids.json 中保存的 episode 列表完成采集后：
envs/model/bin/python scripts/build_stage_a_append_only_data.py
```

`episode 3` 只是单条采集示例，不是全量训练集。删除共享链接后，episode 38 的对齐视频也需在工作副本重新导出：

```bash
CUDA_VISIBLE_DEVICES=0 envs/habitat/bin/python scripts/export_findingdory_sim_history.py --episode 38
```

重新采集与历史回放可能不同，优先用归档的原始输入和缓存结果核对历史成绩。

## 四、代码对应关系

| 步骤 | 代码 |
|---|---|
| 仿真训练数据采集 | `replay_train_experience.py`、`collect_train_batch.py` |
| 建库标签构造 | `build_stage_a_append_only_data.py` |
| 建库 LoRA 训练 | `train_unified_lora_stage_a.py` |
| 自回归生成 Trust 训练记忆 | `generate_autoregressive_memory_shard.py` |
| 六特征、真实标签与 Trust 训练校准 | `build_dual_lora_trust_supervision.py`、`train_dual_lora_trust_heads.py` |
| 合并冻结建库权重以加速推理 | `export_merged_memory_builder.py`，仅合并建库 LoRA，不混合答题 LoRA |
| 全视频追加式建库 | `generate_stage_c_async_memory.py`；另保留 Transformers 版 `generate_stage_c_video_memory.py` |
| 答题训练数据与训练 | `build_stage_c_answer_data.py`、`train_stage_c_answer_lora.py` |
| 分段选帧与帧包展开 | `nb_recall/retrieval_action8.py`、`build_stage_c_action8_data.py`、`build_stage_c_framepack_data.py` |
| 提示词、门控答题与重观察 | `nb_recall/stage_c.py`、`eval_stage_c_answer_batched.py`，恢复了历史门控备份 |
| 映射为官方 episode/task 预测 | `prepare_hlsr_cached_predictions_framepack.py`、`merge_hlsr_sim_replay_predictions_framepack.py` |
| 官方高层判定及汇总 | `eval_findingdory_hlsr_cached_framepack.py`、`aggregate_findingdory_hlsr_cached_framepack.py` |
