# 提交2：FindingDory 42.6% 完整流程归档

本归档对应 `stage_c_validation_3100_framepack`：100 个 episode，5,866 道正式高层任务，成功 2,498 道，**HL-SR = 42.6%**。这是本地按官方高层判定得到的成绩，尚未线上提交。

归档包含从原始模型、训练数据构造、两份独立 LoRA 和 Trust Head 训练，到建库、检索、答题和官方高层判定的代码与产物。**没有收录后来错题补库的答案关联文件，也没有使用“提交1”的答案候选提示。** 检索方法曾根据公开 validation 实验调整，不能称为完全未接触测试集的独立泛化实验。

## 1. 固定的模型与流程

```text
Qwen2.5-VL-3B-Instruct 原始模型
├─ Stage A：训练建库 LoRA（2994 步，之后冻结）
│  图像＋历史摘要 → APPEND 新 Fact/Event 节点和关系；不覆盖历史
├─ Stage B：独立训练并校准两个 Trust Head
│  六项特征 → τ_evidence、τ_fresh；τ = 两者乘积
└─ Stage C：从原始模型新建独立答题 LoRA，使用 checkpoint-3100
   问题＋记忆／重观察图像 → ANSWER、REOBSERVE 或 ABSTAIN

评测视频 → 建库 LoRA 生成 96 帧记忆
→ 问题相关的动作优先分段选 8 帧
→ 96 帧简略索引＋所选 8 帧的完整 Fact/Event/Entity 内容和关系
→ Trust 控制器门控 → 答题 LoRA 输出帧编号
→ 官方仿真状态／PDDL 高层成功判定 → 2498 / 5866
```

“完整帧包”是把**选中的 8 帧**里的多条事实与事件全部展开，不是把全部 96 帧的详细记忆交给模型。这也不同于当前另行训练的全记忆 700 步实验。

## 2. 训练数据与参数

| 阶段 | 数据／输入 | 实际设置与输出 |
|---|---|---|
| Stage A 建库 | 959 个训练 episode 的仿真观察；训练 71,852、校准 9,121、audit 9,167 条，按场景分割 | 两轮，2,994 步；3 卡、每卡微批量 1、累计 16、有效批量 48；LR 1e-4；LoRA r=64、alpha=128、dropout=0.05；384×384 像素预算 |
| Stage B 信任 | 冻结建库 LoRA 的预测与训练场景真实标注比对，构造证据正确性／查询时有效性标签 | 两个 StandardScaler＋LogisticRegression；独立校准集拟合 temperature；具体行数与指标见 `models/nb_recall_dual_lora_trust_heads/report.json` |
| Stage C 答题 | 1,478 个训练视频的模型生成记忆；79,026 个训练问题、192 个留出问题 | READ 88,830 行、GATE 79,026 行，合计 167,856 行；READ/GATE 采样比 70%/30%；3 卡、累计 8、有效批量 24；LR 5e-5；r=64、alpha=128、dropout=0.05；每 100 步存档，采用 3,100 步权重 |

Stage C 原计划 6,994 步，实际停在 3,100 步；`run.json` 的 `complete=false` 是未跑满原计划，不是权重损坏。建库 LoRA、答题 LoRA 都从原始模型独立训练，没有使用官方 Qwen SFT 权重。底层训练脚本和随机种子均保留，重训不承诺逐位重现历史权重。

Stage A 的仿真真实信息用于**训练标签**；评测建库时物体、位置、动作与关系是建库模型的预测，不能把所有这些字段当成真实传感器值。格式校验通过也不等于语义全对。

六个 Trust 输入固定为：`semantic_match`、`provenance_freshness`、`version_consistency`、`conflict_degree`、`support_coverage`、`source_reliability`。温度为 1.52444／1.58170；阈值 `tau_lo=0.4319181543`、`tau_hi=0.6029878128`。高阈值实际采用校准分位数回退，不能声称具有 conformal 风险保证。

## 3. 42.6% 这版的实际推理规则

1. 96 帧划成 8 个连续段，每段 12 帧。优先选择包含 `snap_object`、`desnap_object`、`manipulation_mode`、`full_body_action` 的帧，再按问题提到的物体匹配数量，最后按接近该段中点选帧。
2. 六项特征计算 Trust，保留选中帧的详细内容，附上全部 96 帧的简略时间线。建库结果缓存后复用，答每道题不重新生成整个记忆库。
3. 控制器取选中记忆的最大 τ：高于高阈值直接读记忆答题；介于阈值之间先重看最多 4 张历史证据图；低于低阈值直接弃答。模型请求 REOBSERVE 时再按其编号重看最多 4 张。这里重观察是回看视频帧，不是机器人重新导航。
4. 贪心解码，最多生成 256 tokens，批量最多 8 题、padded-token 预算 65,536，显存不足拆批。这个批量 8 与每题 8 帧是两回事。
5. 返回嵌套帧组；官方转换取每个目标组的第一个编号。无效输出、弃答或非法编号按 `[-1]` 处理，不用标准答案填补输出。

历史预测文件共有 5,876 行；其中 6 行在仿真任务表中不存在，4 行由官方 runner 跳过，正式分母为 5,866。episode 38 使用已有的仿真回放对齐视频及独立 `sim_validation` 记忆。高层评测不运行低层导航，保留了跳过不适用的低层停止诊断的本地适配。历史回放未显式设置 seed，重新运行可能有波动。
