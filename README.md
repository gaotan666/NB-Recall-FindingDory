# NB-Recall · FindingDory

“提交2”的代码协作仓库：从 Qwen2.5-VL-3B-Instruct 出发，训练建库 LoRA、独立 Trust Heads 和答题 LoRA，再进行 FindingDory 高层任务评测。

## 结果

| 方案 | 视频数 | 任务数 | 完成数 | HL-SR |
|---|---:|---:|---:|---:|
| NB-Recall · 提交2 | 100 | 5,866 | 2,498 | **42.6%** |

这是本地按官方高层成功条件得到的历史结果，尚未线上提交。检索配置曾根据公开 validation 实验调整，不能视为完全未接触测试集的独立泛化实验。此版本没有“提交1”的答案辅助补库，也不包含后来使用测评题训练的新答题 LoRA。

分任务成绩和权重哈希见 [结果汇总](results/submission2_summary.json)。离线选帧命中率与上述 HL-SR 是不同指标。

## 方法

```text
Qwen2.5-VL-3B-Instruct
├─ Stage A：建库 LoRA，观察视频并追加事实、事件与关系，保留历史记忆
├─ Stage B：两个独立 Trust Heads，训练并校准证据可信度和时效可信度
└─ Stage C：独立答题 LoRA，使用 checkpoint-3100

每个视频采样96帧 → 建库并缓存
→ 每题按动作与对象匹配，分8个时间段选8帧
→ 96帧简略索引＋所选8帧完整记忆
→ Trust门控：答题／重看最多4张证据图／弃答
→ 输出目标帧 → 官方高层成功判定
```

这里准确保留提交2的历史行为；没有改为后来“完整96帧详细记忆答题”的实验。

## 在已有实验机器上运行

先下载仓库，再通过 `--archive` 指定完整的“提交2”归档。下面示例只创建独立工作目录，不启动训练、不占用GPU：

```bash
python3 scripts/prepare_collaboration_workspace.py \
  --archive /path/to/提交2 \
  --out /path/to/新的实验目录 \
  --mode evaluate
```

程序复用归档资源，并将本仓库的代码复制到新工作目录。因此协作者修改本仓库后，再创建新工作目录即可运行修改后的版本。它不会覆盖原归档或已有实验目录。

```bash
cd /path/to/新的实验目录
# 使用历史权重与缓存记忆重新答题；不会自动启动仿真。
bash scripts/submission2_pipeline.sh answer

# 需要官方高层判定时，再单独运行：
bash scripts/submission2_pipeline.sh hl
```

从头重训时将 `--mode` 改为 `retrain`，按 [完整运行说明](docs/全流程运行说明.md) 的 Stage A → B → 建库 → C → 评测顺序执行。文档中的本机路径是历史示例，请替换为自己的路径。重训不保证逐位复现历史权重或恰好42.6%。

若换到另一台机器，需先共享完整归档及其依赖，按 `environment/` 中的软件包清单准备对应环境；清单是历史环境记录，不是跨平台一键安装保证。
